
# Simulation Module Specification

## 1. Overview

The Simulation module is responsible for creating, calculating, storing, and retrieving subscription pricing simulations.

Each simulation represents an estimate of the subscription cost for a specific customer based on their consumption parameters.

The backend is responsible for validating the input data, calculating the final price, applying the appropriate tax rules, and persisting the simulation results.

## 2. Simulation Data Model

Each simulation must contain the following information:

| Field | Type | Required | Description |
|---|---|---|---|
| id | Integer | Generated | Unique simulation identifier |
| customer_id | Integer | Yes | ID of the associated customer |
| active_users | Integer | Yes | Number of active users |
| storage_gb | Decimal | Yes | Contracted storage in GB |
| estimated_api_calls | Integer | Yes | Estimated number of API calls |
| base_amount_cents | Integer | Generated | Base subscription price in EUR cents |
| tax_rate | Decimal | Generated | Applied tax rate |
| tax_amount_cents | Integer | Generated | Calculated tax in EUR cents |
| total_amount_cents | Integer | Generated | Final price including tax in EUR cents |
| created_at | Datetime | Generated | Simulation creation timestamp |

Calculated fields must be generated by the backend and must not be accepted as trusted values from the frontend.

## 3. API Endpoints

### 3.1. Create Simulation

**Endpoint:** `POST /simulations`

Creates a new simulation for an existing customer.

**Request body:**

```json
{
  "customer_id": 1,
  "active_users": 15,
  "storage_gb": 100,
  "estimated_api_calls": 50000
}
```

**Processing steps:**

1. Validate the request structure and input values.
2. Verify that the specified customer exists.
3. Calculate the base subscription price using the progressive pricing rules.
4. Determine the applicable tax rate according to the customer's country and the defined tax rules.
5. Calculate the tax amount.
6. Calculate the final price including tax.
7. Persist the input parameters and calculated results in SQLite.
8. Return the complete simulation.

**Successful response:** `201 Created`

```json
{
  "id": 1,
  "customer_id": 1,
  "active_users": 15,
  "storage_gb": 100,
  "estimated_api_calls": 50000,
  "base_amount_cents": 14000,
  "tax_rate": 0.21,
  "tax_amount_cents": 2940,
  "total_amount_cents": 16940,
  "currency": "EUR",
  "created_at": "2026-01-15T11:00:00Z"
}
```

The example above assumes a 21% tax rate for illustration. The actual rate must be determined by the applicable tax rules.

**Possible errors:**

| HTTP Status | Error | Description |
|---|---|---|
| 422 | Validation Error | Invalid or missing input values |
| 404 | Customer Not Found | No customer exists with the specified ID |
| 500 | Internal Server Error | Unexpected server error |

### 3.2. Retrieve Simulation

**Endpoint:** `GET /simulations/{simulation_id}`

Retrieves a specific simulation by its ID.

**Successful response:** `200 OK`

Returns the complete simulation object.

**Possible errors:**

| HTTP Status | Error | Description |
|---|---|---|
| 404 | Simulation Not Found | No simulation exists with the specified ID |

### 3.3. Retrieve Customer Simulation History

**Endpoint:** `GET /customers/{customer_id}/simulations`

Retrieves all simulations associated with a specific customer.

The results must be ordered by creation date, newest first.

**Successful response:** `200 OK`

Returns an array of simulation objects.

If the customer exists but has no simulations, an empty array must be returned.

**Possible errors:**

| HTTP Status | Error | Description |
|---|---|---|
| 404 | Customer Not Found | No customer exists with the specified ID |

## 4. Pricing Calculation

The base subscription price depends exclusively on the number of active users.

The pricing model uses progressive pricing tiers:

| User Range | Price per User |
|---|---:|
| 1–10 | €10 |
| 11–50 | €8 |
| More than 50 | €5 |

Each tier applies only to the users within that range.

For example, a simulation with 15 active users is calculated as follows:

- First 10 users: 10 × €10 = €100
- Next 5 users: 5 × €8 = €40
- Base price: €140

Storage and estimated API calls are recorded but do not contribute to the current pricing calculation.

The pricing engine specification is documented separately in `pricing-engine.md`.

## 5. Tax Calculation

The final simulation price includes the applicable tax.

The calculation follows these rules:

- The tax rate depends on the customer's country and applicable tax rules.
- Tax is calculated on the base subscription price.
- Monetary calculations must use precise decimal arithmetic.
- A consistent rounding policy must be applied.
- The applied tax rate and calculated tax amount must be stored with the simulation.

**Formula:**

```text
Tax Amount = Base Price × Tax Rate

Total Price = Base Price + Tax Amount
```

The applicable tax rules and their initial implementation scope must be explicitly defined before implementation.

## 6. Input Validation

The following validation rules apply:

| Field | Validation |
|---|---|
| customer_id | Must reference an existing customer |
| active_users | Integer greater than or equal to 0 |
| storage_gb | Numeric value greater than or equal to 0 |
| estimated_api_calls | Integer greater than or equal to 0 |

Invalid input values must be rejected before any simulation is persisted.

Calculated monetary fields must never be accepted as authoritative values from the frontend.

## 7. Historical Data Consistency

Each simulation must preserve the parameters and calculated results that were valid at the time of creation.

Changes to pricing rules, tax rates, or customer information must not modify previously stored simulations.

The simulation history must therefore represent the original calculation rather than dynamically recalculating historical results.

## 8. Business Rules

- **SIM-BR-01:** Every simulation must belong to an existing customer.
- **SIM-BR-02:** A customer can have multiple simulations.
- **SIM-BR-03:** Active users, storage, and estimated API calls cannot be negative.
- **SIM-BR-04:** The base price is calculated using progressive pricing tiers.
- **SIM-BR-05:** Storage and API calls are recorded but do not affect the current base price.
- **SIM-BR-06:** The applicable tax is calculated on the base price.
- **SIM-BR-07:** All original financial calculations are performed in EUR.
- **SIM-BR-08:** Calculated monetary values are generated by the backend.
- **SIM-BR-09:** Every simulation must preserve its original calculated results.
- **SIM-BR-10:** Simulation history must be ordered from newest to oldest.

## 9. Acceptance Criteria

The Simulation module will be considered complete when:

- [ ] A simulation can be created for an existing customer.
- [ ] Simulations cannot be created for non-existent customers.
- [ ] Negative consumption values are rejected.
- [ ] Active users must be an integer.
- [ ] The progressive pricing calculation produces the expected results.
- [ ] Tax is calculated and included in the final price.
- [ ] Monetary calculations use precise decimal arithmetic.
- [ ] Calculated values are generated by the backend.
- [ ] Simulation data is persisted in SQLite.
- [ ] A simulation can be retrieved by its ID.
- [ ] A customer's simulation history can be retrieved.
- [ ] Simulation history is ordered newest first.
- [ ] Historical results remain unchanged when pricing or tax rules change.
